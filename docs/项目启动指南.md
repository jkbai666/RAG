# 项目启动指南（Windows 新电脑）

适用版本：当前第一版，文档核对日期为 2026-10-20。按 Windows 10/11 x64 和项目现有 PowerShell 脚本编写；Linux、macOS 不直接套用这些命令。

**最短流程：安装下表工具 → 复制源码 → 填两个 API Key → 执行 setup → 执行 start → 打开两个页面。** 首次安装和构建需要联网，之后调用云端模型也需要联网。

## 1. 需要下载哪些工具

以下版本是本项目的运行基线，不是要求下载各工具的最新大版本。已有符合版本的工具可以复用。

| 工具 | 选择的版本 / 安装包 | 官方下载地址 | 安装要点 |
| --- | --- | --- | --- |
| Java JDK | JDK 17，Windows x64，JDK 而非 JRE | [Eclipse Temurin 17](https://adoptium.net/temurin/releases/?version=17) | 可选 MSI；安装完整开发工具，并配置 `JAVA_HOME`、`Path`。 |
| Apache Maven | 3.9.x，Binary zip archive | [Apache Maven 下载](https://maven.apache.org/download.cgi) | 解压到固定目录，将其 `bin` 加入 `Path`；不要选源码包或 Maven 4。 |
| Node.js | 24.x，Windows x64 MSI | [Node.js 下载](https://nodejs.org/en/download) | 选择 24.x，安装时保留 npm 和加入 `Path` 的选项。 |
| Python | 3.12.x，64 位，完整运行环境 | [Python 3.12.10 安装包页面](https://www.python.org/downloads/release/python-31210/) | 页面 Files 中选 **Windows installer (64-bit)**，不要选 embeddable package。记下实际 `python.exe` 路径。 |
| MySQL Community Server | 8.4.x，Windows x86 64-bit ZIP Archive | [MySQL 8.4 下载](https://dev.mysql.com/downloads/mysql/8.4.html) | 解压到固定目录，记下 `bin` 路径；不必注册 Windows 服务或手动建库。 |
| Microsoft Visual C++ 运行库 | x64，MySQL 的 Windows 运行依赖 | [微软官方下载说明](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170) | MySQL 8.4 官方要求 Visual C++ 2019 Redistributable；按微软页面选择兼容的 x64 运行库，已有兼容版本则不必重复安装。 |

Python 版本说明：脚本目前只接受 **3.12**，不要直接安装其他小版本。3.12.10 提供传统 Windows 安装器，但不是最新安全修订版；若有包含后续安全修复的受维护 3.12 发行包，可使用该运行环境并显式传入路径。长期使用应维护安全更新，不能把这里的兼容性基线当成安全更新保证。

**不需要手动安装：** Vue、Vite、Spring Boot、LangChain4j，由 npm / Maven 按项目依赖安装；Chroma 由初始化脚本安装固定版本 `1.5.9`。不需要 Docker、Ollama、llama.cpp、模型权重或独立显卡。拿到源码文件夹即可运行，不强制安装 Git 或 IDE。

### 配置并检查环境变量

在 Windows 的“编辑账户的环境变量”中设置：

- `JAVA_HOME`：JDK 17 的安装根目录，**不是**它的 `bin` 目录。
- `Path`：加入 `%JAVA_HOME%\bin` 和 Maven 的 `bin` 目录。Node.js 一般由安装器配置。
- Python、MySQL 在下文显式指定路径，不要求加入 `Path`。

保存后**重新打开 PowerShell**，执行：

```powershell
java -version
javac -version
mvn.cmd -version
node --version
npm.cmd --version
```

确认 Java / javac 均为 17，Maven 为 3.9.x 且显示使用 Java 17，Node 为 24.x。若不是，先修正 `Path` 中旧版本的优先顺序。

## 2. 把源码放到新电脑

下文以项目放在 `D:\BYS\RAG` 为例。没有 D 盘也可以放到其他可写目录，后续替换 `$Project` 即可。建议使用本地磁盘和简短路径，不放在需要管理员权限的目录。

复制时保留 `backend`、两个 `frontend-*`、`scripts`、`docs`、`tests`、`.env.example`、`README.md`，以及其中的 `pom.xml`、`package.json` 和 `package-lock.json`。注意某些复制工具会漏掉以点开头的文件。

**在新电脑的副本中不要携带以下机器产物：**

- `.local`：包含原电脑的绝对路径、虚拟环境、PID、数据库文件和密码；本指南让新电脑重新生成。
- 两个前端的 `node_modules`、`dist`，以及 `backend/target`：在新电脑重新安装和构建。
- `.idea`、`.vscode`：可不复制。

不要为了准备副本删除旧电脑的数据。本流程得到的是**新的空知识库**，不是历史数据迁移；需要用自己的原始文档重新导入。项目不提供原文件下载，不要把数据库当作原文件备份。

如果 `application.yml` 已填密钥，不要把含密钥的副本发到群聊或公开仓库；可在用于传输的副本中清空两个 Key，到新电脑再填写。

## 3. 获取并填写两个云端 API Key

两个厂商分别开通、分别计费，一个厂商的 Key 不能代替另一个。请在对应账号中确认余额、计费和模型调用权限；本项目不包含免费 Token，也不代购额度。

| 用途 | 厂商与当前配置 | 获取入口 |
| --- | --- | --- |
| 生成回答 | DeepSeek，`deepseek-v4-flash` | [DeepSeek 开放平台](https://platform.deepseek.com/) · [官方 API 说明](https://api-docs.deepseek.com/) |
| 文档和问题向量化 | 阿里云百炼 Qwen，`text-embedding-v4`，1024 维 | [百炼控制台](https://bailian.console.aliyun.com/) · [获取 API Key 官方指南](https://help.aliyun.com/zh/model-studio/get-api-key) |

编辑新电脑的 `D:\BYS\RAG\backend\src\main\resources\application.yml`，找到**已有**的 `rag` 节点，只改对应字段，不要替换整份 YAML 或再加一个 `rag` 节点：

```yaml
rag:
  chat-base-url: https://api.deepseek.com
  chat-api-key: "在这里填写你的 DeepSeek API Key"
  chat-model: deepseek-v4-flash
  embedding-base-url: https://dashscope.aliyuncs.com/compatible-mode/v1
  embedding-api-key: "在这里填写你的百炼 API Key"
  embedding-model: text-embedding-v4
  embedding-dimensions: 1024
```

- 上面的说明文字必须替换成真实 Key，不要保留占位文本。保留英文双引号和 YAML 缩进，不使用 Tab。
- 百炼默认地址是北京区域，Key 必须与调用区域对应；若使用其他区域或业务空间专属地址，按该空间官方示例修改 `embedding-base-url`，不能只换 Key。
- `deepseek-v4-flash` 是项目保留的配置名称；厂商实际路由与可用性以官方平台说明为准。
- 模型配置以此 YAML 为准，**不要把模型 Key 写到前端或 `.local/app.env`**。
- 两个 Key 为空时页面和后端仍可启动，但不能完成向量化和回答。`modelConfigured=true` 只表示配置齐全，不代表真实接口已联通。

## 4. 首次初始化和启动

### 4.1 设置本机路径并检查

打开 PowerShell，先把以下三项改成**新电脑的实际路径**。MySQL 路径要指向解压目录内的 `bin`，不是 ZIP 文件，也不是数据目录。

```powershell
$Project = 'D:\BYS\RAG'
$PythonExe = "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
# 示例使用重命名后的解压目录；请替换为实际路径
$MySqlBin = 'D:\Tools\mysql-8.4\bin'

Set-Location $Project
& $PythonExe --version
& (Join-Path $MySqlBin 'mysqld.exe') --version
Test-Path (Join-Path $MySqlBin 'mysqladmin.exe')
```

预期分别为 Python 3.12.x、MySQL 8.4.x、`True`。任何一项不符，先修正路径或版本。`$PythonExe` 是传统安装器常见的当前用户路径，不保证与你的安装位置相同。

若提示脚本被禁止执行，可在确认源码可信后，仅对当前终端放开脚本执行，再继续下面的命令：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

该设置随当前 PowerShell 退出而失效，不需要永久修改系统策略。若被组织策略禁止，请联系管理员，不要绕过组织策略。

### 4.2 执行初始化（首次必做）

```powershell
& (Join-Path $Project 'scripts\setup.ps1') -PythonPath $PythonExe -MySqlBin $MySqlBin
```

`setup.ps1` 不负责下载上表中的 JDK、Maven、Node、Python 或 MySQL，它会：

1. 检查前置工具；首次生成 `.local/app.env` 和随机数据库密码，已有配置则保留。
2. 初始化项目专用 MySQL 数据目录和账号，创建 `rag_mvp` 数据库；首次初始化期间会启动该实例。表结构由后端启动时通过 Flyway 创建。
3. 建立 `.local/chroma-venv`，安装 `chromadb==1.5.9`。
4. 为两个前端分别执行 `npm ci`。

首次下载可能较慢，看到 `Setup complete` 才算完成；失败时先处理报错，不要直接跳到启动。不需要手动激活虚拟环境、创建表或输入 MySQL root 密码。

**让脚本自动生成 `.local/app.env` 即可，不必先复制 `.env.example`。** 该文件主要保存数据库连接和基础设施配置；修改文件里的密码不会同步修改已有 MySQL 账号密码，不要随意改动。脚本使用独立的 **13306** 端口，不操作已有的 3306 系统实例。

### 4.3 构建并启动全部服务

在同一个 PowerShell 中执行：

```powershell
& (Join-Path $Project 'scripts\start.ps1') -MySqlBin $MySqlBin
```

脚本会启动或复用本项目的 MySQL、Chroma，执行后端 `mvn package`（包含测试）、两个前端的构建，再启动 Java 后端和两个前端页面服务。首次不要加 `-SkipBuild`。

**自定义 MySQL 路径不会被启动参数自动记住。** 上例使用 ZIP 自定义路径，后续每次 `start.ps1` 都要带 `-MySqlBin`。如果采用脚本默认目录 `C:\Program Files\MySQL\MySQL Server 8.4\bin`，可以省略此参数。

## 6. 日常启动、停止和修改配置

**每次重新开 PowerShell，变量都要重新赋值。** 以下示例继续使用上面的自定义 MySQL 路径，请替换成你自己的路径：

```powershell
$Project = 'D:\BYS\RAG'
$MySqlBin = 'D:\Tools\mysql-8.4\bin'
Set-Location $Project

# 未修改源码或 application.yml：复用已有构建启动
& (Join-Path $Project 'scripts\start.ps1') -MySqlBin $MySqlBin -SkipBuild

# 停止本项目登记且进程信息匹配的服务，保留数据
& (Join-Path $Project 'scripts\stop.ps1')
```

修改 API Key 或其他 `application.yml` 配置后：

```powershell
# 先停止后端，避免 start 复用旧进程和旧 JAR
& (Join-Path $Project 'scripts\stop.ps1') -Service backend
# 必须重新构建，不加 -SkipBuild
& (Join-Path $Project 'scripts\start.ps1') -MySqlBin $MySqlBin
```

修改了前端或多处源码时，先用 `stop.ps1` 停止全部项目服务，再运行不带 `-SkipBuild` 的启动命令。不要只关终端来代替停止：服务由脚本在后台启动。初始化和构建中途失败也可能留下已启动的基础设施，可用 `stop.ps1` 停止。

工具安装位置和项目位置确定后不要随意移动，尤其是 `.local/mysql/my.ini` 中写有绝对路径。本文不提供数据库搬迁或自动修复迁移流程。

## 7. 日志、数据和常见问题

以 `D:\BYS\RAG` 为项目目录时：

| 位置 | 内容 |
| --- | --- |
| `D:\BYS\RAG\.local\app.env` | 私有数据库连接、随机密码 |
| `D:\BYS\RAG\.local\mysql\data` | 文档、分块、索引配置等关系数据 |
| `D:\BYS\RAG\.local\chroma` | 向量数据 |
| `D:\BYS\RAG\.local\logs` | 各服务日志，包括 `backend.out.log`、`backend.err.log`、`mysql.log` |
| `D:\BYS\RAG\.local\*.process.json` | 本机进程登记，不是可跨机器复用的启动配置 |

停止服务不会清库；不要删除 `.local` 来解决普通启动问题。若要清空导入内容，优先在文档管理页面删除。换电脑想保留历史知识库时，需要单独备份和迁移 MySQL、Chroma 及相关配置，不能只拷一边。

| 现象 | 处理方法 |
| --- | --- |
| `Missing prerequisite`、找不到 `mvn.cmd` / `npm.cmd` | 检查工具与 `Path`，重新开 PowerShell；命令使用 `.cmd` 可避免误执行同名 npm PowerShell 脚本。 |
| Java 版本不对、构建报 Java 相关错误 | 检查 `mvn.cmd -version` 实际使用的 JDK，修正 `JAVA_HOME` 和旧 Java 路径顺序。 |
| Python 未找到、版本不是 3.12 | 使用完整 `python.exe` 路径传给 `-PythonPath`；不要使用 WindowsApps 的商店别名。 |
| `MySQL 8.4 binaries not found` | `-MySqlBin` 必须指向实际 `bin`，同时包含 `mysqld.exe` 和 `mysqladmin.exe`；setup、start 都传同一路径。 |
| MySQL 缺 DLL 或初始化失败 | 检查 x64 Visual C++ 运行库和 `mysql.log`。数据目录非空且未完成初始化时，脚本会拒绝重置；先查明内容，不盲目删除。 |
| `Port ... is occupied by an unmanaged process` | 13306、8000、8088、5173、5174 需可用。查清端口由谁占用，再决定停止相应程序；脚本不会强杀无关进程。不要只改一处端口，启动检查和前端代理也依赖这些默认值。 |
| pip / npm / Maven 下载失败 | 检查网络、代理及对应官方仓库访问；按组织要求配置可信代理或镜像，不关闭 TLS 校验。安装失败修复后可重跑 setup，构建失败修复后可重跑 start。 |
| 页面能开，上传提示模型未配置 | 检查 YAML 两个 Key 是否非空；停止后端后重新构建。只修改 YAML 或使用 `-SkipBuild` 不会更新 JAR。 |
| 云端报认证、额度、限流或模型不可用 | 核对相应厂商的 Key、余额、权限、模型名、区域和地址；页面可能显示统一服务错误，不一定透传厂商状态码。不要贴完整 Key 到日志截图中。 |
| 问答提示知识库为空 | 先上传文档，等待“就绪”；`PROCESSING` 或失败的文档不参与正常检索。 |
| 换向量模型 / 维度后索引不一致 | 不要混用旧向量；先在旧配置下通过页面删除文档，再修改配置、重建启动并重新导入。不会自动重建索引。 |

只读查看日志示例：

```powershell
Get-Content -LiteralPath (Join-Path $Project '.local\logs\backend.out.log') -Tail 80
Get-Content -LiteralPath (Join-Path $Project '.local\logs\backend.err.log') -Tail 80
Get-Content -LiteralPath (Join-Path $Project '.local\logs\mysql.log') -Tail 80
```

## 8. 使用边界与安全提醒

- 这是本机单用户原型，无登录鉴权，各服务按默认脚本绑定 `127.0.0.1`。不要开放到局域网或公网；Vite preview 不是生产 Web 服务器。
- API Key 写入 YAML 后，源码和构建出来的 JAR 都含有密钥；不要提交、公开或分享。`.local` 中的密码、`admin.cnf` 和 `bootstrap.sql` 同样需要保护。
- 云端向量化会发送文档分块和问题，云端生成会发送问题及检索片段。仅导入允许发给相应厂商的资料。
- 本指南已对照现有脚本及官方安装资料核对；未在另一台全新电脑上完成安装验收，也未代你使用真实 Key 验证云端调用。完成第 5 节才算在目标电脑上跑通了真实链路。

补充参考：[根 README](../README.md) · [HTTP 接口契约](api-contract.md) · [测试说明](../tests/README.md)。MySQL 运行库要求见 [MySQL 官方 Windows 安装说明](https://dev.mysql.com/doc/refman/8.4/en/windows-installation.html)。


## 10. UC-003 升级后的使用变化

这次增加会话记忆和段落切块，不需要安装新工具或填写新的配置项。升级后需要重新构建后端与问答前端；已有工具、两个 API Key、MySQL 和 Chroma 配置继续使用。启动时 Flyway 自动增量创建两个会话表，不要手工重建数据库，不要删除 `.local`。

- 问答端可在同一会话连续追问。完整成功历史存 MySQL，刷新页面或重启后端后可以恢复；浏览器保留当前会话标识，不要清除站点存储。
- 点击「新对话」开始独立上下文；旧记录仍保留，但本版没有历史会话列表。恢复失败时先「重试恢复会话」，不会自动换一个会话继续提问。
- 模型最多使用最近 5 轮完整问答，预算不足时再减少。历史回答不作为本次文档证据；历史来源可能已经被删除。
- 有历史的追问通常多一次 DeepSeek 问题改写调用，增加相应 Token 消耗；最近问答也会随必要上下文发送给生成厂商。
- 新上传改按标题、段落、句子切块，保留重叠。默认 `chunk-size: 800` 是包含重叠的总长度上限，`chunk-overlap: 100` 是重叠上限，均以 Unicode 码点计数。沿用已有 YAML 字段，不要重复添加配置。

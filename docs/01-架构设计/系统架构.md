# 第一版系统架构

本文描述当前实现。需求来源为 UC-001 v2、UC-002 云端接入及 UC-003 会话记忆与段落切块。代码/协议替身、真实浏览器和本机 MySQL 启动验证分别记录；UC-003 不调用付费云端模型，不作为真实回答质量证明。

## 1. 边界与部署

~~~text
问答 Vue 工程 :5173 ──────┐
                         ├── /api 代理 → Java :8088 → MySQL :13306
文档 Vue 工程 :5174 ──────┘                   ├──────→ Chroma V2 :8000
                                             ├──────→ DeepSeek 云端生成
                                             └──────→ Qwen 云端向量
~~~

两个 Vue 工程分别安装、构建和启动，共享一个 Java 进程，不共享浏览器内存。两端通过普通新标签页链接互相访问，问答端恢复焦点时刷新知识库状态。本机服务监听均为回环地址，模型通过出站 HTTPS 调用云端；无身份认证、用户隔离或公网入口。

Java 17 + Spring Boot 3.5.16；LangChain4j core / OpenAI 1.22.0，Chroma 适配 1.22.0-beta32，显式使用 V2 的 default_tenant/default_database；PDFBox 3.0.7 解析文本型 PDF。前端为 Vue 3.5.44 + TypeScript + Vite 8.3.4。

## 2. 数据职责

MySQL 是展示和引用的权威来源：

| 表 | 职责 |
| --- | --- |
| rag_documents | 文件名、格式、大小、状态、分块数、创建时间、失败原因、清理与删除标记 |
| rag_chunks | 稳定块 ID、文档 ID、连续序号、完整正文、PDF 页码范围；外键级联删除 |
| rag_settings | 向量模型及索引配置摘要，阻止旧向量与新模型混用 |
| rag_conversations | UUID 会话与创建时间 |
| rag_conversation_exchanges | 会话/请求 UUID 绑定、问题、成功 Answer JSON 快照、完成时间与稳定序号；失败占位无成功响应 |

Flyway V1 维护原有资料表，V2 只增量创建会话表，不改 V1 或重切资料。MySQL schema 与用户由隔离环境初始化脚本准备。Chroma collection 保存同一块 ID 的向量、文本和 documentId 元数据，是可派生索引，不是分块详情的数据源。文件内容在导入中处理，本版不提供原始文件归档或下载；展示、恢复查询依赖持久化后的正文。

## 3. 文档导入

1. 检查单文件、扩展名和 20 MiB 上限；文件名只作显示，不能变成磁盘路径。
2. 写入 PROCESSING，返回 202。单个工作线程异步执行，最多五个在途导入；队列满时明确拒绝。
3. TXT/MD 严格解码 UTF-8；PDF 按页提取文本，记录页跨度。拒绝无正文、损坏或加密的 PDF，不做 OCR。
4. 按标题、自然段选择主体；长段按完整句子拆分，附加紧邻前文重叠，保留连续原文。生成稳定 UUID，先写 MySQL 块记录。
5. 分批请求向量模型，以相同 ID 写 Chroma。全部完成后才置 READY。
6. 任一环节失败置 FAILED，并尝试按已记录 ID 清理向量；清理失败保留标记，定时重试。非 READY 文档不能用于问答。

正文上限为 400 万 UTF-16 单元，避免将单个文件无限展开。YAML 默认每块总上限 800 码点（包括最多 100 码点重叠）；首块无重叠，前文不足取实际长度。主体按边界推进，不用固定长度滑窗；PDF 软换行不强制分段，页码包括重叠来源。不可安全分割的超长句子或代码围栏明确导入失败，不偷偷硬切。新策略只用于之后导入，既有知识库不重索引。text-embedding-v4 使用 1024 维 float 向量，SDK 每个 HTTP 请求最多 8 段。应用不以字符串截断代替模型能力校验。

## 4. 问答与来源

问答端通过会话 API 使用 MySQL 保存的历史，而不是让浏览器提交任意历史。最多取最近 5 轮完整问答，预算不足移除最旧整轮；原 `/api/chat` 保留无记忆兼容行为。问题验证非空、Unicode 有效和最多 2000 码点；空库 409，未配置模型 503。

有可用历史时先用 DeepSeek 将当前问题补全成独立检索问题；改写结构校验失败返回 502。检索问题向量 → Chroma 最多五个候选 → MySQL READY 与删除标记复核 → 在预算内加入完整分块与必要问答 → DeepSeek 关闭 thinking 并返回 JSON。改写和生成分别核算完整提示、输入 JSON 与输出预留；当前问题和证据优先于历史。分块和问题作为不可信数据传入，系统提示词要求只据原文、不执行其中的指令。

历史只用于理解对话，不作为知识库证据。新问题无有效召回时直接给出无依据；历史来源即使仍可展示，也不作为新引用。模型回答须包含 answer、grounded、citationIds，引用必须来自实际给出的完整块；无效结构或伪造 ID 返回 502。有依据时再从 MySQL 复核并返回原文快照；没有依据返回 grounded=false、sources=[]。这能验证引用 ID 和正文对应关系，不能从算法上证明回答每句话都忠于原文，仍需用户核对。

配置齐全只表示 modelConfigured=true，不意味着外部服务可达。模型或 Chroma 失败返回 502，识别到超时返回 504，不能伪装成知识库没有答案。

### 会话恢复与幂等

服务器生成会话 UUID，客户端为一次发送生成 requestId。单进程分段锁串行化同会话，数据库唯一约束绑定请求与问题；重复成功请求先返回持久化结果，不重复付费调用。失败仅留标识占位，不进入完成历史；同标识不同问题返回 409。完成记录按完成时间与稳定序号排序，避免早先失败重试插回旧位置。

前端 localStorage 仅保存当前会话 ID 和待确认请求（含原问题）；成功历史与来源始终从服务端恢复。恢复失败保留标识，需显式重试或新对话，不自动替换。发送期间禁止新对话；刷新或浏览器断线不能保证取消后端执行，若后端已完成则通过恢复和幂等重放取回结果。

「新对话」只建立新上下文，不删除旧记录。完整成功历史持久保存，5 轮限制仅用于模型上下文。本版无历史会话列表、会话删除、跨会话记忆或多用户鉴权；不要把恢复接口暴露到公网。历史来源快照可包含后来删除的文档，页面会明确提示。

## 5. 删除、恢复和一致性

MySQL 与 Chroma 之间没有分布式事务，采用稳定 ID、状态门禁和可重试清理：

- PROCESSING 暂不能删除，避免导入与删除竞争。
- 删除先把文档标记为不可检索，再清 Chroma，最后删除关系记录。失败保留文档和原因，用户可重试；后台清理不会冒充前端删除成功。
- 问答持有读锁直至回答与来源校验结束，删除持有写锁，提供单进程内明确的先后顺序。
- 启动将残留 PROCESSING 转 FAILED；定时清理其已知向量。不会自动恢复原文件任务，应删除后重新导入。
- 两类存储都落本机目录，常规停止不删除数据。UC-001 曾用旧本地模型验证三项服务重启后分块与问答仍可用；这不是新云端模型的持久化验收。

这些约束只适用于单后端实例；不支持水平扩容或多实例并发恢复。

## 6. 安全与运行约束

模型配置与两个 Key 在服务端 application.yml 中，数据库凭据在私有 app.env；模型配置不再从旧 app.env 加载。填写真实 Key 后，源码与 JAR 均含凭据，不可提交或分享。日志与错误不回显模型凭据或上游响应；页面用 Vue 文本插值，不用 v-html 渲染正文。跨库故障时优先保证不把未完成或已删除的文档作为来源。

默认使用云端模型：向量化会把文档分块和问题发送给百炼，生成会把问题、必要的最近问答与检索分块发送给 DeepSeek；有历史的追问可能增加一次问题改写请求。Key 为空时不发模型请求，无本地回退，默认脚本不下载或启动本地模型。DeepSeek 使用用户指定的兼容名 deepseek-v4-flash；2026-10-20 官方文档说明实际路由至 DeepSeek-V4.1-Flash-1017。

当前 collection=rag_qwen_v4_1024。更换向量模型须先在旧配置下删除旧文档，再切换 collection 并重新导入；不支持自动重建或在线迁移。UC-002 曾按用户追加授权删除旧模型资料；UC-003 未清理既有文档、分块或向量。部署前后内容摘要一致，详见本次验证记录。

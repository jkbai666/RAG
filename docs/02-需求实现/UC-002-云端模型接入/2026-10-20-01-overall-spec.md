# 云端模型接入规格

| 项目 | 内容 |
| --- | --- |
| 编号 | UC-002 |
| 日期 | 2026-10-20 |

## 1. 范围与决定

- D-001：将“量化模型”按当前 RAG 语境解释为向量模型。使用百炼 text-embedding-v4（基于 Qwen3），1024 维，生成使用 DeepSeek 官方兼容接口和用户指定的 deepseek-v4-flash 名称。
- D-002：官方在 2026-10-20 的文档说明旧名 deepseek-v4-flash 仍接受，但实际路由到 DeepSeek-V4.1-Flash-1017。本项目保留用户指定的兼容名，明确不承诺已退役的旧权重。
- D-003：两项 API Key 都在 backend/src/main/resources/application.yml 预留空字符串，旁注用途。基础 URL、模型名、分块与维度配置一并放在该文件。空 Key 启动成功、状态为未配置，上传缺 Key 返回 503；问答沿用空库优先 409、有就绪文档时缺 Key 为 503 的契约，不回退本地模型。
- D-004：默认不启动或下载 llama.cpp / GGUF。旧 .local/app.env 的模型值不得覆盖新 YAML；数据库凭据仍来自本机私有环境文件，保留数据，不连接原有 3306 实例。
- D-005：DeepSeek 请求明确关闭 thinking，并使用 JSON 输出；向量请求 float 编码、1024 维，批次不超过官方 text-embedding-v4 上限 10。分块恢复为 800 / 100。
- D-006：保留现有索引配置摘要防混用机制，新 collection 使用 rag_qwen_v4_1024。不得擅自清空用户文档。用户随后明确授权删除已导入文档，本轮通过旧服务的正常删除接口清理两份现有记录及旧向量，不直接清表。后续更换模型仍需先在旧配置下删除，再重新导入。
- D-007：不改前端功能或 API 契约，不新增账号、模型选择页面或自动重建。真实 Key 不打印、不入测试报告；填写真实 Key 后源码和 JAR 均视为含凭据，不可分享或提交。

## 2. 验收标准

| 编号 | 可观察标准 |
| --- | --- |
| AC-001 | YAML 明确预留两个 Key，默认云端 URL / model / 1024 维，空 Key 不会被旧本机配置替代。 |
| AC-002 | 用本地 HTTP 协议测试验证实际 LangChain4j 请求的路径、鉴权、模型名、维度、批次、thinking disabled 和 JSON 参数；不冒充真实厂商调用。 |
| AC-003 | 空 Key 时后端仍启动，health 正常、modelConfigured=false，上传返回 503；空库问答保持 409，有就绪文档时缺 Key 为 503，均不发模型请求。 |
| AC-004 | setup / start 默认不依赖本地模型文件，不下载或拉起本地模型；只运行数据库、Chroma、Java 和两个前端。 |
| AC-005 | 现有测试和构建通过；数据库不被脚本重置，仅按用户追加授权删除已核实的两份原有文档；文档同步配置入口、隐私和 Key 缺失的验证边界。 |

## 3. 核对来源

- DeepSeek 官方首次请求、thinking 和 JSON 输出文档；百炼 text-embedding-v4 模型、同步向量接口和 Base URL 文档，均于 2026-10-20 核对。
- 具体官方文档链接与实际结果记入验证记录。没有云端 Key，因此不进行有费用的真实厂商请求。

## 4. 批准记录

用户本轮直接要求修改代码并预留 application.yml 中的 API Key，授权本地实现与验证，不授权购买、账号操作、提交推送或生产发布。随后补充“为了方便起见，我导入的文档可以直接删掉”，授权清理当前导入的文档；不涉及其他数据库或系统文件。

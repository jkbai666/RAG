## 1. 技术与接口基线

- Java 17.0.20.1、Spring Boot 3.5.16，LangChain4j 1.22.0 / Chroma 集成 1.22.0-beta32，MySQL 8.4.9，Chroma 1.5.9（V2 API）。已完成实际构建及真实向量增查删验证。
- 两个独立 Vue 3.5.44 + TypeScript + Vite 8.3.4 工程：`frontend-chat/`、`frontend-docs/`。不用后台框架，不引入账号体系。
- Java 服务 `backend/` 监听 `127.0.0.1:8088`，问答端 `127.0.0.1:5173`，文档端 `127.0.0.1:5174`；MySQL 自有实例 `13306`，Chroma `8000`。若冲突由主 agent 调整并统一文档。
- 模型使用服务端可配置的 OpenAI 兼容接口，生成与向量模型独立配置。未配置时后端可启动，明确返回配置错误；禁止用 mock 回答冒充实际问答。已安装本地生成及向量模型并完成真实闭环。
- 所有数据放在本项目 `.local/` 或容器数据卷，不连接现有 3306 实例；忽略凭据、数据库文件、模型缓存和日志。

## 3. 验证顺序与证据

1. `mvn -f backend/pom.xml test` 和两个前端各自 `npm run build`，记录具体版本及结果。
2. 在本项目专属 MySQL 和真实 Chroma 上验证向量增查删，然后通过后端验证 TXT、MD、PDF 导入、分块、失败处理、删除、重启持久化。
3. 接入实际可用的生成及向量模型，验证有答案、无答案、来源真实、模型故障；无可用凭据时不得将该项标记通过。
4. 使用真实浏览器走通两个前端；检查 1440×900 和 390×844、键盘、空态、等待、错误和重复提交，保留可复现的测试脚本和截图。
5. 文档按 humanizer-zh 校订；运行需求包校验；实现后再更新实际架构、README 和索引。

## 4. 回滚与安全

只停止本项目启动且已核对 PID 的进程。不停止或重置既有 MySQL。删除数据必须明确指向本项目 `.local/`，常规停止不清数据。真实凭据不入仓库、不写前端、不打印。没有提交、推送、PR 或生产发布授权。

### 5.1 实施调整与修复

- 采用 Qwen3-1.7B Q8 + BGE-small-zh-v1.5 Q8，由 llama.cpp CPU 服务提供 OpenAI 兼容接口，无需外部 Key。模型版本与 SHA256 固定在 scripts/model-manifest.json，不将大模型文件放入源码。
- BGE 输入上限 512 tokens，本机配置从建议 800 / 100 调整为 300 / 50 Unicode 码点，512 维；代码缺省值仍保留，超限明确失败，不静默截断。
- 集成中明确使用 Chroma V2；MySQL 正文为权威、稳定块 ID 与状态门禁保证分块展示和检索可核对。删除和导入失败采用可重试清理，不引入分布式事务或新基础设施。
- Windows 上正在运行的 JAR 不能安全覆盖，start 检测现有项目后端并复用构建；修改源码需先 stop 再 start。进程停止依据已登记 PID 和命令行 marker 核对，MySQL 优先正常关闭。
- 浏览器标题定位器曾将装饰字符算入名称，修正测试定位器后回归通过；未将其当作产品缺陷。

## 6. 保留边界

- 本机单用户、无鉴权；不作公网、多人、生产或模型效果承诺。
- 远程认证错误、真实超时、网络半写入、导入后跨标签自动刷新状态的完整时序、读屏与跨浏览器未专项验证；零召回不调用生成模型由后端单元覆盖。
- 容器备选、异机全新首次安装、压力与安全审计未实测。Flyway 对 MySQL 8.4 有支持范围警告，但实际迁移与重启校验通过。
- 没有 Git 提交、推送或 PR，也未创建仓库。
